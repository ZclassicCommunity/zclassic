# Defensive coding in zclassicd

How to write C++, C and shell in this tree so that a hostile peer, a crash, a bad option or a careless log line cannot hurt a node or its wallet. Each numbered rule names a zclassicd example by path and symbol and the lint rule or test that enforces it where one exists. The live code is the authority: the `<!-- claim: ... -->` markers below are checked by `zcl-lint doc-claims`, so a rule whose example disappears fails the lint instead of going stale.

Adapted from Z23's defensive coding standard (Z23 `docs/DEFENSIVE_CODING.md`), rewritten for C++, Boost and autotools. Rules that only make sense for Z23 (its ActiveRecord lifecycle, SQLite cursors, result types) are not carried over. Consensus rules are out of scope here: read [CONSENSUS_PARITY.md](CONSENSUS_PARITY.md) before touching a validation path. <!-- doc-path-ok -->

## Untrusted P2P input and size limits

Every byte from a peer is hostile until a bounded reader has accepted it.

1. **Read peer data only through the serializers, and let their caps stand.** `ReadCompactSize` in `src/serialize.h` rejects a non-canonical encoding and any size above `MAX_SIZE` (32 MiB) by throwing `std::ios_base::failure`; vectors and strings decode through it. Never add a hand-rolled length prefix or a raw `memcpy` from `vRecv`. Use `LIMITED_STRING` for strings with a protocol maximum. <!-- claim: symbol-present ReadCompactSize src/serialize.h --> <!-- claim: symbol-present MAX_SIZE src/serialize.h --> <!-- claim: symbol-present LIMITED_STRING src/serialize.h -->
2. **A message is bounded before it is parsed.** `CNode::ReceiveMsgBytes` in `src/net.cpp` disconnects a peer whose header announces more than `MAX_PROTOCOL_MESSAGE_LENGTH` (2 MiB, `src/net.h`), so no single message can make the node allocate more. A new message type inherits that cap; it does not need a bigger one. <!-- claim: symbol-present MAX_PROTOCOL_MESSAGE_LENGTH src/net.h -->
3. **Check the element count of a decoded list at once, and score the peer.** The `inv` and `getdata` handlers in `ProcessMessage` (`src/main.cpp`) compare `vInv.size()` with `MAX_INV_SZ` (50,000, `src/net.h`) right after `vRecv >> vInv` and call `Misbehaving(pfrom->GetId(), 20)`. Follow the same shape for any new list: decode, check the count against a named constant, score, return. <!-- claim: symbol-present MAX_INV_SZ src/net.h --> <!-- claim: symbol-present Misbehaving src/main.cpp -->
4. **Catch a malformed payload where it is parsed when it must cost ban score.** `ProcessMessages` catches `std::ios_base::failure`, `std::exception` and `...` around each message, logs and moves on, but accrues no ban score. A handler that must punish malformed input catches the failure itself, as the bootstrap chunk request handlers in `src/main.cpp` do ("Malformed payload must be scored here"). Never let an exception escape a handler thread: `PrintExceptionContinue` (`src/util.cpp`) is the last resort, not the plan. <!-- claim: symbol-present ProcessMessages src/main.cpp --> <!-- claim: symbol-present PrintExceptionContinue src/util.cpp -->
5. **Sanitize a peer-supplied string before it reaches a log.** Commands and sub-versions go through `SanitizeString` (`src/utilstrencodings.h`) before `LogPrintf`; the sub-version is capped at `MAX_SUBVERSION_LENGTH`. <!-- claim: symbol-present SanitizeString src/utilstrencodings.h --> <!-- claim: symbol-present MAX_SUBVERSION_LENGTH src/net.h -->
6. **A log argument is evaluated even when its category is off.** `LogPrint` in `src/util.h` is an inline function, not a macro that skips its arguments, so an argument that throws (`CInv::ToString` on an unknown type, `src/protocol.cpp`) throws whether or not `-debug=net` is set. Format only values that cannot throw, or guard with `IsKnownType`. See [TRAPS.md](TRAPS.md) section 8. <!-- claim: symbol-present LogAcceptCategory src/util.h --> <!-- claim: symbol-present IsKnownType src/protocol.cpp -->
7. **Every network-facing decoder has a fuzz target.** `src/test/fuzz/` holds `fuzz_block`, `fuzz_tx` and `fuzz_p2p_payload`, built by `src/test/fuzz/build-fuzz.sh`; the Boost suites `p2p_message_limits_tests` and `wire_robustness_tests` drive `ProcessMessages` with crafted bytes. Add a corpus entry or a Boost case with a new decoder. <!-- claim: file-present src/test/fuzz/fuzz_p2p_payload.cpp --> <!-- claim: file-present src/test/p2p_message_limits_tests.cpp --> <!-- claim: file-present src/test/wire_robustness_tests.cpp -->

## Integer overflow and amounts

8. **Range-check every amount, and every running sum, with `MoneyRange`.** `MoneyRange` and `MAX_MONEY` in `src/amount.h` are consensus values. `CheckTransactionWithoutProofVerification` in `src/main.cpp` checks each output and the running total after every addition (`bad-txns-vout-toolarge`, `bad-txns-txouttotal-toolarge`), and `CheckTxInputs` checks input values (`bad-txns-inputvalues-outofrange`). New code that adds `CAmount` values checks after each step, not only at the end, so a sum cannot wrap past the check. <!-- claim: symbol-present MoneyRange src/amount.h --> <!-- claim: symbol-present CheckTxInputs src/main.cpp -->
9. **Parse user amounts with `ParseMoney` (`src/utilmoneystr.h`) and refuse what does not parse.** `AppInit2` in `src/init.cpp` turns a bad `-minrelaytxfee` or `-mintxfee` into `InitError("Invalid amount ...")` rather than a default. <!-- claim: symbol-present ParseMoney src/utilmoneystr.h -->
10. **Size arithmetic on input-derived lengths is done in a wider type and compared before use.** In C code linked into the daemon (`src/c23/glue/`, `src/zcash/tree_root.c`) use `size_t` or `uint64_t` and check `a > SIZE_MAX - b` before `a + b`. `__builtin_add_overflow` is available on every release compiler; `<stdckdint.h>` is not (GCC 9).

## Locks and lock order

11. **Lock order is `cs_main`, then `cs_wallet`, then `mempool.cs`; never the reverse.** Take two at once with `LOCK2(cs_main, cs_wallet)` (`src/sync.h`). `CWallet::SetBestChain` holds `cs_main` and `cs_wallet` for the whole checkpoint because Berkeley DB here runs no deadlock detector. The order is recorded in `src/AGENTS.md`, [TRAPS.md](TRAPS.md) section 2 and the FACTS row `setbestchain-lock-order`. <!-- claim: symbol-present LOCK2 src/sync.h --> <!-- claim: symbol-present SetBestChain src/wallet/wallet.cpp -->
12. **State a lock precondition with `AssertLockHeld`, and know it is silent in release builds.** `AssertLockHeld` aborts only when the build defines `DEBUG_LOCKORDER` (`./configure --enable-debug` adds it, `configure.ac`); otherwise `AssertLockHeldInternal` is an empty inline. `ConnectBlock` opens with `AssertLockHeld(cs_main)`. Run new locking code once in a debug build. <!-- claim: symbol-present AssertLockHeldInternal src/sync.h --> <!-- claim: symbol-present enable_debug configure.ac --> <!-- claim: symbol-present DEBUG_LOCKORDER src/sync.cpp -->
13. **A debug build reports lock-order inversions; read debug.log for them.** `potential_deadlock_detected` in `src/sync.cpp` logs "POTENTIAL DEADLOCK DETECTED" with both lock stacks ([doc/developer-notes.md](../developer-notes.md)). <!-- claim: symbol-present potential_deadlock_detected src/sync.cpp -->
14. **Use `TRY_LOCK` where blocking would stall a network thread.** `SendMessages` takes `TRY_LOCK(cs_main, lockMain)` and skips work when it fails. A flag shared between threads is written and read under the same lock, or is a `std::atomic`; a plain `bool` written by two threads without a common lock is a data race (see `fPingQueued` in [TRAPS.md](TRAPS.md) section 8). <!-- claim: symbol-present TRY_LOCK src/sync.h --> <!-- claim: symbol-present SendMessages src/main.cpp -->

## Threads and interruption

15. **Long-running threads start through `TraceThread` in the shared thread group.** `TraceThread` (`src/util.h`) names the thread and catches and reports its exceptions; `AppInit2` adds threads with `threadGroup.create_thread`, and `Interrupt` in `src/init.cpp` calls `interrupt_all` at shutdown. <!-- claim: symbol-present TraceThread src/util.h --> <!-- claim: symbol-present interrupt_all src/init.cpp -->
16. **Loops in those threads reach an interruption point.** `boost::this_thread::interruption_point()` or `MilliSleep` (`src/utiltime.cpp`, a `boost::this_thread::sleep_for`) let `interrupt_all` stop the thread. `std::this_thread::sleep_for` and `sleep_until` are not interruption points: `ThreadNotifyRecentlyAdded` in `src/init.cpp` sleeps on the standard clock and then calls `interruption_point`, so it can delay shutdown by up to a second. Prefer `MilliSleep` in new loops. <!-- claim: symbol-present MilliSleep src/utiltime.cpp --> <!-- claim: symbol-present ThreadNotifyRecentlyAdded src/init.cpp -->
17. **Shutdown is requested, not forced.** Call `StartShutdown` and poll `ShutdownRequested` (`src/init.h`); never `exit()` from a worker. The only deliberate `_exit` is the `-testcrashpoint` hook (`TestCrashPoint` in `src/util.cpp`), which `AppInit2` refuses outside regtest. <!-- claim: symbol-present StartShutdown src/init.h --> <!-- claim: symbol-present ShutdownRequested src/init.h -->

## Durable writes

18. **A file that must survive a crash is written to a temporary name, committed, renamed and its directory synced.** `WriteCleanMarker` in `src/shutdownmarker.cpp` is the model: write `shutdown.clean.tmp`, `FileCommit`, `RenameOver`, then `DirectoryCommit` (all in `src/util.h`). Never rewrite a live file in place. <!-- claim: symbol-present WriteCleanMarker src/shutdownmarker.cpp --> <!-- claim: symbol-present DirectoryCommit src/util.h --> <!-- claim: symbol-present RenameOver src/util.h -->
19. **A Berkeley DB commit in the wallet is not on disk.** `CDBEnv::Open` in `src/wallet/db.cpp` sets `DB_TXN_WRITE_NOSYNC`, so durability comes from `CDB::Flush`, `CDBEnv::CheckpointLSN`, `ThreadFlushWalletDB` and the shutdown flush. A new wallet write that must survive a crash says which of those makes it durable. What is written when: [doc/wallet-crash-consistency.md](../wallet-crash-consistency.md). <!-- claim: symbol-present DB_TXN_WRITE_NOSYNC src/wallet/db.cpp --> <!-- claim: symbol-present ThreadFlushWalletDB src/wallet/walletdb.cpp -->
20. **A copy of a live database is verified before it replaces anything.** `BackupWallet` in `src/wallet/walletdb.cpp` writes an exclusive temp file, syncs it, compares `HashFileSHA256` of source and copy, then renames (`qa/rpc-tests/backupwallet_atomic.sh`). <!-- claim: symbol-present BackupWallet src/wallet/walletdb.cpp --> <!-- claim: symbol-present HashFileSHA256 src/util.h -->

## RPC errors

21. **Every RPC failure throws `JSONRPCError` with a code and a sentence the caller can act on.** `JSONRPCError` and the `RPC_*` codes are in `src/rpc/protocol.h`; for example `getblock` throws `JSONRPCError(RPC_INVALID_ADDRESS_OR_KEY, "Block not found")` (`src/rpc/blockchain.cpp`). A bare `false`, an empty object or a generic "error" is not an answer. <!-- claim: symbol-present JSONRPCError src/rpc/protocol.h --> <!-- claim: symbol-present RPC_INVALID_PARAMETER src/rpc/protocol.h -->
22. **Check parameter types before use.** `RPCTypeCheck` (`src/rpc/server.h`) refuses a wrong type with a message naming it; calls that need the chain loaded are refused with `RPC_IN_WARMUP` and the warm-up status (`src/rpc/server.cpp`). Wallet calls that need keys call `EnsureWalletIsUnlocked` (`src/wallet/rpcwallet.cpp`). <!-- claim: symbol-present RPCTypeCheck src/rpc/server.h --> <!-- claim: symbol-present RPC_IN_WARMUP src/rpc/protocol.h --> <!-- claim: symbol-present EnsureWalletIsUnlocked src/wallet/rpcwallet.cpp -->

## Start-up and option validation

23. **A bad option or an unsafe state stops start-up with `InitError`; it is never silently defaulted.** `InitError` in `src/init.cpp` shows the message and makes `AppInit2` return false. Examples: an invalid fee amount; an interrupted GUI repair (`chain-repair-pending.json`) refuses to open a mixed database pair; a locked data directory names the holder (`DescribeLockHolder`). Use `InitWarning` only when continuing is safe. <!-- claim: symbol-present InitError src/init.cpp --> <!-- claim: symbol-present DescribeLockHolder src/init.cpp -->
24. **Test-only hooks are refused outside regtest.** `-testcrashpoint` and the other `-test*` options are accepted on regtest only (`src/init.cpp`, FACTS row `test-crash-hooks`), so no production node can be told to exit. A new test hook follows the same gate.

## Logging privacy

25. **Never log or print a key, seed, mnemonic, passphrase or spending key.** `zcl-lint secretlog` (`zcutil/lint/rules/secretlog.c`) flags log and print calls in `src/` and `wallet/src/` whose arguments name `CKey`, `strWalletPass`, `SecureString`, `seed`, `mnemonic`, `passphrase` and similar; a `log-ok: reason` comment overrides one line, and every baseline row is a finding to review. <!-- claim: symbol-present lint_rule_secretlog zcutil/lint/rules.def --> <!-- claim: symbol-present strWalletPass zcutil/lint/rules/secretlog.c -->
26. **Do not put secrets in argv or in test fixtures that leave the machine.** Command lines are visible to every local user; pass a passphrase over RPC (`walletpassphrase`) or stdin, and keep wallet fixtures in an isolated datadir that the test deletes.

## C23 glue and vendored code

27. **Vendored C is verbatim.** `src/c23/vendor/**` and `src/c23/services/vendor/**` change only through `revendor.sh` and are checked by `src/c23/tools/check-vendor.sh` (`zcl-lint vendor`). A file that must differ moves to `src/c23/glue/` with a "derived from Z23" header ([src/c23/AGENTS.md](../../src/c23/AGENTS.md)). <!-- claim: file-present src/c23/tools/check-vendor.sh --> <!-- claim: symbol-present lint_rule_vendor zcutil/lint/rules.def -->
28. **Every global of `libzcl_c23.a` is prefixed.** `src/c23/glue/zcl_c23_symbol_prefix.h` is force-included and renames each core name to `zc23_<name>`, so it cannot collide with libsodium or OpenSSL; `src/c23/tools/symbol-prefix.sh check` fails on an unprefixed export and `gen` regenerates the header. <!-- claim: file-present src/c23/glue/zcl_c23_symbol_prefix.h --> <!-- claim: file-present src/c23/tools/symbol-prefix.sh -->
29. **C linked into the daemon compiles as gnu17 with zero warnings.** Release builds use GCC 9: no `nullptr`, `constexpr`, attributes, `typeof`, `_BitInt` or `#embed`. `src/Makefile.am` builds the core with `-std=gnu17` and sets `-D__USE_MINGW_ANSI_STDIO=1` for `%zu` on MinGW; `src/c23/glue/zcl_c23_compat.h` enforces the platform contract with `_Static_assert`. Check with `sh src/c23/tools/build-check.sh <cc> -std=gnu17 <outdir>`. <!-- claim: symbol-present libzcl_c23_a_CPPFLAGS src/Makefile.am --> <!-- claim: symbol-present _Static_assert src/c23/glue/zcl_c23_compat.h -->
30. **No unbounded string calls in new code.** `zcl-lint banned-str` counts `strcpy`, `strcat`, `sprintf`, `vsprintf` and `gets` in non-vendored C and C++ against a shrink-only baseline; use `snprintf` and check the result for truncation. `lint-ok:` exempts a line only with a reason. <!-- claim: symbol-present lint_rule_banned_str zcutil/lint/rules.def -->
31. **No new warning suppressions.** `zcl-lint warnsupp` counts `#pragma ... diagnostic ignored` and `-Wno-` in sources and build fragments; fix the warning instead. <!-- claim: symbol-present lint_rule_warnsupp zcutil/lint/rules.def -->

## Tests

32. **Every test runs in its own data directory.** `TestingSetup` in `src/test/test_bitcoin.cpp` points `-datadir` at a fresh `GetTempPath()` directory and removes it; qa scripts make a `mktemp -d` work directory and clean it up on EXIT, INT and TERM ([qa/AGENTS.md](../../qa/AGENTS.md)). `zcl-lint testiso` flags a literal `/tmp/`, a default datadir without `-datadir=` and a fixed `-port=` or `-rpcport=` in qa scripts (`iso-ok: reason` overrides). <!-- claim: symbol-present TestingSetup src/test/test_bitcoin.h --> <!-- claim: symbol-present lint_rule_testiso zcutil/lint/rules.def -->
33. **Ports are leased, never derived from the PID.** qa scripts call `iso_base` or `lease_ports` from `qa/lib/isolation.sh`, which take a free block from `zcl-port` ([qa/lib/README.md](../../qa/lib/README.md)); `$((20000 + ($$ % 20000)))` collided under parallel runs. <!-- claim: symbol-present lease_ports qa/lib/isolation.sh --> <!-- claim: symbol-present iso_base qa/lib/isolation.sh -->
34. **An assertion is never decided by elapsed wall-clock time.** A loaded host makes such a test flaky, and the fix is never a bigger number. Use `SetMockTime` (`src/utiltime.h`) in unit tests and poll for a state in qa scripts. `zcl-lint wallclock` flags assertions that compare elapsed real time (`real-clock: reason` overrides). <!-- claim: symbol-present SetMockTime src/utiltime.h --> <!-- claim: symbol-present lint_rule_wallclock zcutil/lint/rules.def -->
35. **Never weaken an assertion, a tolerance or a timeout to make a run pass.** Find the cause. `step()` in `zcutil/local-ci.sh` gives each step a wall-clock limit and a log cap on purpose. <!-- claim: step-exists test_bitcoin-full -->

## Shell glue

36. **Shell is POSIX `sh`, and only where C would be heavier.** `zcl-lint no-new-bash` counts bash shebangs and bashisms (`[[`, `<(`, arrays, `echo -e`) per file against a shrink-only baseline; `no-python` (`zcutil/check-no-python.sh`) refuses Python anywhere. New tooling is C. <!-- claim: symbol-present lint_rule_no_new_bash zcutil/lint/rules.def --> <!-- claim: file-present zcutil/check-no-python.sh -->
37. **Shell must run on Linux, macOS and Git Bash.** `zcl-lint shellport` flags `sed -i`, `stat -c`, `nproc`, `ss`, `readlink -f`, `date -d`, `grep -P`, `timeout` and `| grep -q` under `pipefail` (`port-ok: reason` overrides a guarded use). Use `getconf _NPROCESSORS_ONLN` for a CPU count and the port helper instead of `ss`. <!-- claim: symbol-present lint_rule_shellport zcutil/lint/rules.def -->
38. **Check the artifact, not the exit status behind a pipe.** `cmd | tee log` returns `tee`'s status; read the log, the footer, the hash sidecar or the receipt ([TRAPS.md](TRAPS.md) section 4).
