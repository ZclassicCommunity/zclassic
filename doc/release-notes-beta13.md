# ZClassic Wallet and Node 2.1.2-beta13

Beta13 is a new wallet **and** a new node (both v2.1.2-beta13). The shielded cryptography no longer uses Rust or libsnark: it is the C23 core in `src/c23`. Start-up and balance queries are faster, shielded sends use less memory, wallet state survives hard kills and chain reorganisations with correct balances, and syncing from block 0 works again.

**No consensus rule, checkpoint, activation height or the IBD proof-skip is changed**, by any change listed below either. The only edit to a sealed consensus file since the first beta13 notes removes a dead DNS seed from `src/chainparams.cpp`; it is a network seed, not a consensus parameter. One owner-approved consensus-adjacent change: the 413 historical oversize transactions are admitted by an explicit allowlist (the same table Z23 uses), which is what makes a sync from block 0 possible.

## What is new
- **No Rust, no libsnark.** Sapling, Sprout (Groth16 and PHGR13) and Equihash verification are C23, checked against a manifest. `sprout-proving.key`, libgmp and OpenMP are no longer needed. New Sprout PHGR13 proofs can no longer be created (they only existed before Sapling); they are still verified.
- **Faster.** Proof verification about 2x; Equihash checked once per block; start-up of a full mainnet node about 24 s to 8 s; `z_getbalance` with 3,252 notes 1.29 s to 0.012 s; note scanning up to 4x faster with many addresses.
- **Less memory.** Peak for a 20-40 note shielded send about 850 MB to about 390 MB.
- **Wallet reliability.** A hard kill can no longer leave a spent shielded note counted as unspent. A reorganisation no longer aborts the daemon, and after a reorganisation or `-reindex` the wallet's own unmined sends are offered to the mempool again, so the running wallet shows the same balance as after a restart. Shielded sends check their anchors and witnesses before proving. `backupwallet` now copies to a temporary file, syncs, compares SHA-256 and only then renames into place; it works without `-exportdir`.
- **Node reliability.** Sync from block 0 works. `-reindex` no longer silently drops blocks after a stale record header; `invalidateblock` is reliable across restarts. Peer address selection no longer stalls, and a fresh node holds its outbound peers. Interrupted snapshot downloads resume, with every kept file re-verified. New `-mempoolmaxbytes` (default 300 MB).
- **Faster peer connections.** A fresh node dials several addresses at once, gives an address it has never reached a shorter first-contact timeout (2 seconds; later attempts use `-timeout`), uses the built-in fixed seeds as soon as its address table is thin, and no longer waits on a DNS seed that stopped resolving (`dnsseed.zslp.org` is removed). Measured on a Windows home PC, median of 5 fresh starts: 3 peers in 0.75 s (was 8.6 s), 5 peers in 6.4 s (was 35 s or never), first block in 0.69 s (was 2.02 s). Your results depend on your network.
- **Fast sync from several snapshot servers at once.** The snapshot download spreads its streams over every snapshot server it knows, takes identical files from whichever server has them, hashes each file while it downloads, keeps going when a server goes away, and a node killed while the snapshot is being installed now recovers by itself on the next start. `getbootstrapinfo` gains `servers` and `servers_in_use` while several servers are used, and the wallet shows the number of servers next to the download speed. Every byte is still verified against the trusted snapshot manifest, exactly as before; the snapshot protocol is unchanged.
  - The node now has four built-in snapshot servers (two more than before), each also reachable as a Tor v3 onion service for onion-only nodes.
- **Wallet: smaller and safer.** Notes that were spent long ago no longer get their witnesses updated or rewritten after every block (a spent note record is about 4.6 KiB instead of about 77 KiB), which makes the wallet file smaller and each block cheaper to process. `z_sendmany` takes an optional `idempotency_key`; with it the wallet keeps a durable send journal, so a send you retry after a timeout, a crash or a restart returns the first operation and cannot pay twice. `z_listsendjournal` lists the journal, see [doc/send-journal.md](send-journal.md). `getwalletinfo` has a `health` object (checkpoint, witnesses, pending sends) and the wallet shows a one-line "Wallet needs attention" notice only when something in it needs attention.
- **Node speed and limits.** A cache of verified Sapling shielded transactions lets a block skip the proof checks it already did when the transaction entered the mempool (`-maxshieldedcachesize`, default 4 MiB, `0` disables); header Equihash solutions are checked on several threads (`-headerprecheck`, default on); LevelDB open-file limits follow the system file-descriptor limit (override with `-dbmaxopenfiles`, shown by `-help-debug`); after a clean shutdown the next start checks only the last 6 blocks, while a crash, a kill or any change to the block or database files runs the usual full check (`-cleanshutdownmarker`, default on). None of these changes which blocks or transactions are accepted.
- **Node diagnostics.** `getrpcinfo` lists the RPC calls in flight and per-method counts and times (method names only, never parameters); calls slower than `-rpcslowlog=<ms>` (default 1000, `0` disables) are logged as a warning. When the RPC server is overloaded it answers HTTP 503 with a message that names `-rpcworkqueue` and `-rpcthreads` instead of dropping the call. On Linux and macOS, the error for a data directory that another process already holds now names that process. `-help` now lists `-equihashimpl`, `-finalizationdelay`, `-finalizationminpeers`, `-finalizationrequirepeers`, `-maxreorgdepth`, `-paramcache`, `-parkdeepreorg` and `-uacomment`.
- **Tor (off by default).** Optional embedded Tor (`-embeddedtor=1`) with fixed onion v3 handling.
- **Updated components.** OpenSSL 3.5.9.
- **Windows.** Non-ASCII data directories work, and the node shuts down cleanly when its console is closed.
- `debug.log` is off by default; use `-debuglogfile` to enable it.

## For developers
The source tree has no Python and no hosted CI: the developer tools are C (`zcl-dev`, `zcl-lint`, `jsonq`, a git-hook agent guard and an MCP server), and release candidates are built and tested on the project's own machines. Contributor and agent rules are in `AGENTS.md`; the guides for agents and the commands that read them are in `doc/agent/`.

## Upgrading
Close your old wallet normally, keep your wallet and data directory, and open the new one. A wallet backup first is recommended; do not delete or reindex your data directory. Beta13 reads existing `wallet.dat` files.

## Downloads
- **Windows x86_64 wallet:** `zclwallet-v2.1.2-beta13-win64.exe`, a single file with the node embedded. No installer; run it.
- **Linux x86_64 wallet:** `zclwallet-v2.1.2-beta13-linux-x86_64` (glibc 2.31+, system X11/XCB/font libraries).
- **macOS Apple Silicon wallet:** `zclwallet-v2.1.2-beta13-macos-arm64.dmg` (macOS 14 or later; tested natively on macOS 26). Intel Macs are not supplied.
- **Command-line node** (`zclassicd`, `zclassic-cli`, `zclassic-tx`): `zclassicd-v2.1.2-beta13-win64.zip`, `zclassicd-v2.1.2-beta13-linux-x86_64.tar.gz`, `zclassicd-v2.1.2-beta13-macos-arm64.tar.gz`.

Verify a download against `SHA256SUMS.txt` (for example `sha256sum -c SHA256SUMS.txt --ignore-missing`, or `Get-FileHash` on Windows). `BUILDINFO.txt` records the source commit, toolchains and checks for each file.

## Unsigned builds
These builds were made on our own machines, not on GitHub Actions, and are **not code-signed**. Windows SmartScreen may warn: choose "More info", then "Run anyway". The macOS wallet and node are ad-hoc signed, not Apple-notarized: Gatekeeper may refuse the first launch; right-click the app and choose Open, or allow it under System Settings, Privacy & Security.

## Known issues
- A pruned node cannot reorganise onto a reconsidered fork that is more than 288 blocks heavier (the undo data is gone).
- New Sprout PHGR13 proofs can no longer be created (see above); existing ones are still verified.
- Windows 7 and Windows 10 older than 1903 are untested; 32-bit targets no longer build.
- Tor is pinned to the `RhettCreighton/tor` fork with patches carried in `depends`; it stays off by default.
- Going back to an older wallet (beta12 or before) after a wallet that has spent many shielded notes ran on this version is safe: balances and notes stay correct, also after importing a key with rescan. One limit: if the first thing the older wallet does is to roll back four or more blocks (an orphaned tip or `invalidateblock`) and you then import a key with rescan, it counts old spent notes as unspent until it runs once with `-rescan` or this version opens the wallet again (which repairs it by itself). Nothing is spent twice. Normal running is faster by the share of the wallet that is spent (those notes are no longer updated per block or rewritten); every unspent note is still written after each block.

## Verification
The release files are built from one source commit, recorded in `BUILDINFO.txt` on the release page and in `SOURCE_COMMIT.txt` inside each node archive. The work up to [PR161](https://github.com/ZclassicCommunity/zclassic/pull/161) was verified on Linux, macOS arm64 and real Windows with the unit suites, the golden corpus, a real mainnet block replay (3,327,490 blocks, 0 failures), kill-and-verify cycles with no spent-note mismatches, reorganisation and `invalidateblock` tests, a node synced from block 0 identical to a snapshot-synced node (same best block and UTXO-set hash at height 3,321,763), and a 3-hour mainnet soak with flat memory. The work added after it ([PR162](https://github.com/ZclassicCommunity/zclassic/pull/162): connections, fast sync from several servers, the wallet changes, the node changes and the tooling) was reviewed change by change by a reviewer that is not its author and verified with the unit suites and the shell tests on Linux, macOS arm64 and real Windows; that pull request records the results.

For the release files: each node binary is hardening-checked (PIE/RELRO/NX/canary on Linux, DYNAMIC_BASE/NX_COMPAT/HIGH_ENTROPY_VA on Windows, PIE on macOS); the Windows wallet imports only Windows system DLLs and passes the embedded-daemon extraction check against the node hash; the macOS disk image is verified and mounted read-only with a valid ad-hoc signature; the Linux wallet passes extraction and HTTPS checks. `BUILDINFO.txt` records the toolchains and the checks run on these exact files. No funded public-mainnet send test and no universal sync-time claim is made.
