# Wiring for the C23 KAT and mutation suite (unit U4)

Everything in `src/c23/test/` is TEST-ONLY. Nothing here is linked into
`zclassicd`, `zcash-gtest`, `test_bitcoin` or any shipped binary, and unit U4
changed no `configure.ac` or `Makefile*.am`. This file lists what a build owner
may add.

## What the suite is

| file | role |
|---|---|
| `kat_common.{c,h}` | ABI declarations (C), golden tokenizer, portable abort isolation (fork on POSIX, self re-exec on Windows), UTF-16 init paths on Windows |
| `kat_jub.{c,h}` | Jubjub/BLS12-381 helpers from the vendored Z23 primitives, used only to craft inputs (re-signed signatures, `y+q` / `x+p` encodings) and to check randomized RedJubjub signatures with Rust's cofactored equation |
| `kat_replay.c` | replays every record of `src/test/data/c23_golden` (45,991 records, 31 functions) through the C23 shim; `--prove` re-runs every prover and `--emit` writes the C23-made proofs as a case file for the Rust verifier |
| `kat_mutgen.c` | writes `vectors/mutations.cases` (mutations not in the golden corpus) |
| `kat_cases.c` | runs a case file through whichever ABI it is linked with, and `--compare`s two result files |
| `kat_threads.c` | 16-thread concurrency check (cold warm-up before init, then check_spend / check_output / merkle_hash / ka_agree after init); meant for `-fsanitize=thread` too |
| `kat_bench.c` | per-call timing on fixed golden inputs; the same source links the C23 shim or the Rust `librustzcash.a` |
| `make-pdir.sh` | builds the parameter directory the `init:` mutation cases use (reads the real params, never writes them) |
| `run.sh` | builds and runs everything against the C23 shim (Windows MSYS2 or Linux) |
| `rust.sh` | builds `kat_cases_rust` / `kat_bench_rust` against a Rust-backed `depends` prefix and produces Rust's results |
| `vectors/mutations.cases` | generated by `kat_mutgen` (deterministic); `run.sh` regenerates it and fails if it differs |
| `vectors/mutations.rust.out` | Rust librustzcash 06da3b9a output for `mutations.cases` (produced by `rust.sh` on x86_64 Linux) |

## Running it

```sh
# C23 only (no Rust). Needs the Zcash params for init and proving.
sh src/c23/test/run.sh --out <dir> [--cc clang] [--std -std=c23] [--prove] \
    [--san "-fsanitize=address,undefined -fno-sanitize-recover=undefined"]
sh src/c23/test/run.sh --out <dir> --cc clang --san -fsanitize=thread --threads-only --steps threads
# Rust oracle twin (only while a Rust-backed depends prefix exists)
sh src/c23/test/rust.sh --depends <prefix> --out <dir> --steps build,mutations
sh src/c23/test/rust.sh --depends <prefix> --out <dir> --steps c23made \
    --cases <dir>/c23made.cases --expect <dir>/c23made.expect
```

On Windows run it from Git Bash with the MSYS2 UCRT64 compilers first on `PATH`
and `TMP`/`TEMP`/`TMPDIR` set to a Windows-form writable directory (gcc reads
`TMPDIR` first). Do not run it from the MSYS2 `/usr/bin/sh`, which drops those
variables.

## Optional Automake hook (not applied)

If the build owner wants it in `make check`, the least intrusive form is a
script test that calls `run.sh` when the parameters exist:

```make
# src/Makefile.test.include (UNTESTED; U4 does not edit it)
EXTRA_DIST += c23/test/run.sh c23/test/rust.sh c23/test/make-pdir.sh c23/test/WIRING.md \
  c23/test/kat_common.c c23/test/kat_common.h c23/test/kat_jub.c c23/test/kat_jub.h \
  c23/test/kat_replay.c c23/test/kat_cases.c c23/test/kat_mutgen.c c23/test/kat_threads.c \
  c23/test/kat_bench.c c23/test/vectors/mutations.cases c23/test/vectors/mutations.rust.out
check-c23-kat:
	sh $(srcdir)/c23/test/run.sh --out $(builddir)/c23-kat --cc $(CC)
```

`run.sh` compiles its own copy of the vendored sources, glue, shim and Sprout
prover (with `zcl_c23_test_glue.c`, never the daemon glue); it does not use
`libzcl_c23.a`. `rust.sh` must never be part of the zclassicd build (it needs
`librustzcash.a`). After U9 deletes Rust from `depends`, `vectors/mutations.rust.out`
is the frozen Rust answer for the mutation cases, as the goldens are for the corpus.
